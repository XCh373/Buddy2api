## 实现内容

| 文件 | 交付内容 |
| --- | --- |
| `account_routing.py` | 严格配置校验；缓存可信度；额度时间、周期、单位和余额边界；本地消耗的保守扣减；最高手动 priority 内的最早临期分组 |
| `auth_manager.py` | 新策略接入原 picker；最佳组内保留粘性；安全、只读路由预览；按账号串行资源刷新；记录成功基线与失败状态；取消时撤销缓存可信度 |
| `database.py` | 一次连接批量读缓存；保留成功快照时间的失败标记；原子设置保存；损坏缓存对象的容错 |
| `routing_refresh.py` | lifespan 所有的单个后台任务；最大并发 2；25 秒资源任务上限；优先账号刷新通知；整轮定时刷新不会被频繁通知推迟；关闭策略后不发起新的策略查询 |
| `server.py` | 启停后台任务；验证并保存 `workbuddy_routing`；管理鉴权下的只读 `/admin/routing/preview` |
| `control_plane.py` | 开启策略且生命周期任务存在时，成功领取后排队刷新资源；其他场景保留原资源刷新行为 |
| `web/index.html` | Settings 中新增路由设置和已保存策略预览；保存/恢复默认；原账号列表排序维持展示用途 |
| `tests/test_expiry_routing.py` | 78 个测试实例，覆盖新增策略、数据、worker、生命周期、接口与真实代理选号链路 |
| `README.md`、`README_EN.md` | 使用说明、默认参数与精度限制 |

默认 `legacy`；启用 `expiry_first` 后仅影响 WorkBuddy。默认窗口 30 天、刷新间隔 120 秒、缓存最大年龄 300 秒。手动 priority 优先；相同 priority 下按最早到期组选择，同组保持粘性。可信额度信息不足时回原策略，不能因新增缓存策略额外产生无账号错误。

没有数据库表结构迁移。新增设置与资源缓存字段由旧代码忽略；这并不代替未来部署前的备份与兼容检查。
